ARCHITECTURE

Implement the following agent architecture:

AGENT 1 — MARKET DATA AGENT
Purpose:
- Receive the stock watchlist.
- Call fetch_ohlcv_batch() exactly once for the selected stocks.
- Validate returned data.
- Report missing/invalid symbols.
- Ensure downstream agents can access cached OHLCV data.

AGENT 2 — TECHNICAL ANALYST
Purpose:
Calculate and interpret technical indicators for each selected stock.

Use these indicator groups:

TREND:
- EMA20
- EMA50
- EMA200
- ADX

MOMENTUM:
- RSI
- MACD
- ROC
- Stochastic Oscillator
- TSI

VOLUME:
- OBV
- CMF
- MFI
- PVO

VOLATILITY:
- ATR
- NATR
- Bollinger Band Width
- Donchian Channels

STATISTICAL:
- returns
- rolling z-score
- rolling skewness

Use pandas/pandas_ta where appropriate, but implement robust fallbacks where necessary.

AGENT 3 — QUANT/ML ANALYST
Purpose:
- Generate a feature matrix from historical OHLCV and technical indicators.
- Predict the probability that a stock will have a positive short-term forward return.
- Use a simple, explainable ML model such as RandomForestClassifier or HistGradientBoostingClassifier.
- Use a TIME-BASED train/validation split. Never randomly shuffle time-series data.
- Define a target such as positive 5-day forward return.
- Avoid look-ahead bias and data leakage.
- Output:
  symbol
  prediction_probability
  ML score
  model information
  important features if available.

AGENT 4 — NEWS ANALYST
Purpose:
- Retrieve recent news for each selected stock through a configurable news API/tool.
- Analyse positive/negative/neutral sentiment.
- Produce a normalized News Score from 0–100.
- News must be one input to the decision rather than the sole decision-maker.
- If no news API is configured, the system must continue gracefully and use a neutral news score.

AGENT 5 — SIGNAL ANALYST
Purpose:
Combine the analytical outputs into a deterministic composite score.

Use:

Technical Score = 60%
ML Score = 20%
News Score = 10%
Risk Score = 10%

Final Score = weighted combination of these components.

Normalize every component to 0–100.

Decision thresholds:

80–100 = STRONG BUY
70–79 = BUY
55–69 = HOLD
40–54 = WEAK HOLD
0–39 = SELL

The final score must be calculated by deterministic Python code, NOT invented arbitrarily by the LLM.

For each stock output:

symbol
technical_score
ml_score
news_score
risk_score
final_score
decision
conviction
rationale

AGENT 6 — PORTFOLIO STRATEGIST
Purpose:
- Take all stock decisions together.
- Consider current holdings, available cash and portfolio exposure.
- Rank opportunities by final score.
- Decide which stocks to buy, hold or sell.
- Enforce portfolio rules.

Implement configurable rules:

- maximum position size: 10% of portfolio
- minimum cash reserve: 10%
- configurable maximum number of new buys
- configurable maximum number of sells
- avoid excessive concentration
- account for high-beta/growth-satellite stocks
- use current holdings before recommending new trades
- do not buy a stock merely because it has a high score if portfolio constraints make it inappropriate.

AGENT 7 — RISK AND EXECUTION AGENT
Purpose:
- Act as the final gatekeeper before paper-trade execution.
- Validate position size.
- Validate available cash.
- Check existing positions.
- Check open orders.
- Check portfolio exposure.
- Prevent duplicate/conflicting orders.
- Calculate ATR-based stop-loss and take-profit levels.
- Require optional human confirmation before executing trades.

Example risk rules:

Stop loss:
entry price - 2 × ATR

Take profit:
entry price + 3 × ATR

These should be configurable.

If human approval is enabled:

ANALYSIS
→ PORTFOLIO PLAN
→ RISK CHECK
→ SHOW PROPOSED ORDERS
→ USER APPROVAL
→ ALPACA PAPER ORDER

If approval is disabled, execution can proceed only when all automated risk checks pass.
